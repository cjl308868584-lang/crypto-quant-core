# Binance funding rate type compatibility

Verified on 2026-08-31 against Binance's public USDⓈ-M documentation.

## Official contract

- Binance added `rateType` to `GET /fapi/v1/fundingRate` on 2026-07-23.
- The only documented values are the case-sensitive strings `Regular` and
  `Special`. `Special` means an additional funding rate generated by stock
  dividends.
- Sources: [USDⓈ-M change log](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/change-log)
  and [Funding Rate History](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data).

The official documents do not define `fundingRateType=REGULAR`. That shape is
therefore a project legacy format, not a historical Binance API claim.

## Project boundary

- New public acquisitions emit capture schema `2.1.0`, require exactly
  `rateType=Regular|Special`, and preserve it as normalized `rate_type`.
- Schema `2.0.0` remains loadable only for strict replay of the exact project
  legacy shape `fundingRateType=REGULAR`; new acquisition never emits it.
- Missing, dual, unknown or case-changed type fields fail closed. Invalid
  decimals, invalid times, duplicate/non-increasing funding times and
  normalized/raw disagreements also fail closed rather than being merged or
  guessed.
- Raw response bytes remain in the request ledger. The canonical artifact,
  self-hash and strict replay therefore bind both the original field shape and
  the normalized evidence.

This compatibility change uses public fixtures only. It does not authorize or
perform credential access, private requests, account reads, orders, fund
movement, service startup, activation, release or deployment.

PR integration binds the new `2.1.0` fixtures and changed inputs in this
branch's `BUILD_CANDIDATE` evaluator manifest so CI can verify the whole tree.
It does not rewrite the `v0.78.7` tag or authorize merge, release or deployment;
any future tagged release still requires a separate approved identity.
